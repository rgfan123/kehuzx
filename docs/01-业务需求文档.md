# 客户、样品及订单管理系统业务需求文档

## 1. 文档信息

- 文档版本：V1.0
- 编制日期：2026-08-19
- 文档状态：初稿，供产品确认和开发使用
- 适用范围：客户、客户需求、样品模板、样品订单、样品订单流程、正式订单、正式订单流程、供应商档案

## 2. 项目目标

建设一套围绕客户需求、产品打样和正式订单流转的业务管理系统，帮助使用者完成以下工作：

1. 建立客户档案并持续维护客户需求。
2. 根据客户需求制作单产品样品模板。
3. 从多个样品模板复制产品信息，组成一张包含多个产品的样品订单。
4. 跟踪样品订单从沟通、制作到客户确认的完整流程。
5. 将已确认的模板用于创建包含多个产品的正式订单。
6. 跟踪正式订单的制作和交付流程。
7. 在订单产品明细中按需关联外部供应商；未选择供应商表示由本公司供应。

## 3. 业务主流程

```text
创建客户档案
  -> 在客户详情新增一条或多条客户需求
  -> 根据需求创建样品模板（一个模板对应一个产品）
  -> 选择一个或多个模板加入样品订单草稿
  -> 补充各产品数量、可选供应商及整单交付/结账信息
  -> 提交样品订单并按流程流转
  -> 客户确认样品
  -> 将相关模板改为“已被供应”
  -> 选择一个或多个模板加入正式订单草稿
  -> 补充数量、可选供应商及整单交付/结账信息
  -> 提交正式订单并按流程流转
```

## 4. 页面与导航

### 4.1 一级导航

```text
客户
样品
  - 样品模板
  - 样品订单
  - 样品订单流程
正式订单
  - 正式订单列表
  - 正式订单流程
供应商
```

### 4.2 客户列表

客户以条状列表展示，默认每页 5 条，支持分页。

每条客户展示：

- 客户名称
- 客户编号
- 客户分类
- 公司名称
- 联系人
- 联系电话
- 微信号
- 客户状态
- 创建时间
- 需求数量
- 样品订单数量
- 正式订单数量
- 操作：查看详情、修改、删除

页面支持新增客户，并至少支持按客户名称、客户编号、公司名称、联系人和联系电话搜索。

### 4.3 客户详情

客户详情是单个客户的业务入口。页面顶部展示客户基本信息，下方使用标签页或子页面展示：

1. 客户需求
2. 样品模板
3. 样品订单
4. 正式订单

各标签页只展示当前客户的数据，默认每页 5 条，并支持相应的新增、查看、修改和删除操作。

### 4.4 样品模板页面

展示所有客户的全部样品模板。一个模板只代表一个产品。

主要展示字段：

- 模板编号
- 模板名称
- 所属客户
- 产品基础信息摘要
- 单份供价摘要
- 模板状态
- 创建时间

操作：复制为新模板、加入样品订单、加入正式订单、查看、修改、删除。

支持按模板编号、模板名称、所属客户、产品基础信息、模板状态和创建时间筛选。默认每页 5 条。

### 4.5 样品订单页面

展示所有客户的全部样品订单，支持增删改查。列表主要展示：

- 样品订单编号
- 样品订单名称
- 所属客户
- 产品明细数量
- 产品摘要
- 创建时间
- 交付时间
- 当前流程状态
- 是否中止

操作：查看、修改、删除。默认每页 5 条。

订单详情展示整单信息和全部产品明细。

### 4.6 样品订单流程页面

按以下状态展示样品订单：

1. 样品沟通
2. 工厂沟通
3. 样品制作中
4. 样品制作完成
5. 顾客送样
6. 成品确定

页面可以使用状态标签页或状态导航。选择状态后，仅展示当前状态的订单。支持按客户、订单编号/名称、产品、创建时间和交付时间筛选。

每条订单提供：

- 查看详情
- 进入下一流程
- 中止
- 已中止时取消中止

每个状态列表默认每页 5 条，并支持新增、查看、修改、删除。

### 4.7 正式订单及流程页面

正式订单列表的交互和样品订单列表一致，流程状态为：

1. 订单沟通
2. 工厂沟通
3. 订单制作中
4. 订单制作完成
5. 送达顾客

正式订单流程页面支持按客户和其他订单条件筛选，并提供查看详情、进入下一流程、中止和取消中止操作。默认每页 5 条。

### 4.8 供应商页面

当前阶段只建设供应商档案列表和基础增删改查。供应商以条状列表展示，默认每页 5 条。

## 5. 数据字段

### 5.1 通用规则

- 数据库内部 ID 由系统生成，用户不可编辑。
- 各业务对象另有唯一业务编号，由系统自动生成并用于展示和搜索。
- 名称由用户填写，除客户需求外的主要业务对象均应具备名称。
- 创建时间由系统生成，更新时间由系统维护。
- 空内容在数据库中保存为 `NULL`，页面统一显示“无”，不得把字符串“无”写入数字、日期、布尔或外键字段。
- 金额不得小于 0，建议保留两位小数。
- 长度、宽度、厚度和数量不得小于 0。
- 删除客户、模板、订单等业务数据时采用软删除，历史记录不得物理丢失。

## 6. 复制与快照规则

1. 从客户需求创建模板时，复制需求中的产品基础信息。
2. 模板加入订单后，在订单产品明细中保存产品、规格和价格快照。
3. 模板后续修改不得改变已经创建的订单历史内容。
4. 一张订单可以连续加入多个模板，形成多条产品明细。
5. 同一模板重复加入订单时，系统应提示，由使用者确认是否重复添加。
6. 模板的“复制”操作至少提供：复制为新模板、加入样品订单、加入正式订单。

## 7. 草稿与提交校验

为兼顾快速录入和数据完整性，采用分阶段校验：

### 7.1 保存草稿

- 名称必填。
- 其他业务字段允许暂时为空。
- 样品模板状态默认为“草稿”。
- 订单草稿不进入流程统计页面。

### 7.2 提交订单

- 所属客户必填。
- 至少包含一条产品明细。
- 每条产品明细的产品名必填。
- 每条产品明细必须填写有效数量。
- 交付时间必填。
- 提交成功后自动进入第一个流程状态。

## 8. 流程与中止规则

1. “进入下一流程”只能按预设顺序前进，普通用户不能跳级。
2. 最终状态不显示“进入下一流程”按钮。
3. 中止不是流程状态，而是独立运行状态。
4. 中止时必须填写中止原因，并记录中止时间和中止前流程状态。
5. 已中止订单不能进入下一流程。
6. 取消中止后恢复到中止前的流程状态。
7. 每次流程变化均记录原状态、新状态、操作人、操作时间和备注。
8. 删除、中止、取消中止和进入下一流程均需二次确认。

## 9. 搜索、分页与展示

- 所有列表默认每页 5 条。
- 分页由服务端执行，返回总条数和当前页数据。
- 搜索条件支持组合使用和一键重置。
- 时间搜索使用开始时间和结束时间。
- 默认按创建时间倒序排列。
- 空字段统一展示“无”。
- 长文本在列表中截断，详情中完整展示。

## 10. 非功能要求

- 页面布局适配常用桌面分辨率，并保证移动端不发生内容遮挡。
- 表单需提供明确的必填、格式和范围校验提示。
- 所有写操作需要给出成功或失败反馈，避免重复提交。
- 列表加载、空数据、接口失败和无权限状态均应有明确界面。
- 关键业务操作应记录审计日志。
- 后端必须再次校验权限和业务状态，不能只依赖前端按钮控制。

## 11. 当前建议规则（待产品最终确认）

以下内容来源于方案建议，开发前可再次确认：

1. 样品模板“所属客户”是否强制必填；本文建议必填。
2. 模板状态是否最终使用“草稿、可用于样品、已被供应、停止供应”。
3. “总体数量”是否始终由单份数量乘份数计算，是否允许人工覆盖。
4. 结账金额是否完全人工填写，还是由产品金额、税额和配送费计算后允许调整。
5. 客户进入“成品确定”后，是否自动把相关模板改为“已被供应”，还是弹窗确认后批量修改。

## 12. 第一阶段验收标准

1. 可以建立客户，并在客户详情中管理多条需求。
2. 可以从需求创建单产品模板，模板默认状态为草稿。
3. 可以选择多个模板组成一张样品订单。
4. 每个订单产品可以独立选择供应商或选择不关联供应商。
5. 修改模板不会影响历史订单中的产品快照。
6. 样品订单和正式订单可以按指定状态逐级流转。
7. 订单可以填写原因后中止，也可以取消中止并恢复原状态。
8. 客户详情可以查看该客户的需求、模板、样品订单和正式订单。
9. 全局列表和客户详情列表均默认每页 5 条并支持搜索、分页。
10. 所有关键操作和流程变化具有可追溯记录。
