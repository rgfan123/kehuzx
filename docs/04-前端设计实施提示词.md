# 前端设计实施提示词

你是一名擅长企业级 ERP、订单履约和物流运营系统的高级前端工程师兼产品设计师。请基于当前仓库实现“客户、样品及订单管理系统”的前端界面。

## 一、开始前必须执行

完整阅读：

- `docs/01-业务需求文档.md`
- `docs/02-开发指导.md`

同时检查仓库中的 README、`AGENTS.md`、现有页面、组件库、路由、状态管理、API 客户端、样式规范和测试工具。优先复用现有项目结构，不擅自重写无关代码。

技术要求：

- 前端组件库：Ant Design 5。
- 前端使用 React 与 TypeScript；若仓库已有具体构建工具和版本，沿用现有配置。
- 后端：FastAPI。前端通过清晰的类型定义和统一 API 客户端调用后端。
- 不在组件中散落请求地址，不使用隐式 `any`，不把正式数据长期保存在前端模拟对象中。
- 如果接口尚未完成，可以建立类型明确的接口适配层和临时 mock，但必须易于切换到真实 FastAPI 接口，并清楚标记 mock 边界。

## 二、设计目标

将系统设计成现代企业级 ERP / SaaS 运营中台，视觉和交互参考订单履约、供应链及物流管理系统。

系统面向需要高频查找客户、编辑产品明细、处理订单和推进流程的内部运营人员。设计优先级为：

1. 信息清晰，能够快速扫描。
2. 高频操作路径短，反馈明确。
3. 表格、筛选和表单具有较高信息密度，但不拥挤。
4. 同一业务对象在全局页面和客户详情中的交互保持一致。
5. 状态、异常和下一步操作一眼可辨。

不要做成营销网站、数据大屏或装饰性后台模板。避免巨大标题、大片留白、过度卡片化和没有业务意义的图表。

## 三、视觉语言

### 3.1 基础风格

- 使用浅色主题。
- 页面背景为浅蓝灰色，建议从 `#F3F6FA` 附近取值。
- 主内容容器为白色。
- 主色使用低饱和商务蓝，建议从 `#3F6F9F` 至 `#4A78A8` 范围选取。
- 成功色使用克制绿色，警告色使用棕黄色，异常色使用暗红色。
- 边框使用浅灰蓝色，分割线清楚但不抢眼。
- 禁止渐变、玻璃拟态、发光效果、夸张阴影、装饰性插画、彩色背景团块和纯视觉装饰。
- 圆角保持克制：常规容器 8px；弹窗、抽屉和 Ant Design 组件遵循统一令牌。
- 阴影只用于浮层或需要建立层级的内容，常规页面容器使用边框和极轻阴影即可。

### 3.2 建议设计令牌

通过 Ant Design 5 `ConfigProvider` 主题令牌和项目级 CSS 变量集中管理，不在页面中反复写魔法颜色。

```text
colorPrimary:       #4676A9
colorBgLayout:      #F3F6FA
colorBgContainer:   #FFFFFF
colorBorder:        #DCE3EA
colorBorderSecondary:#E8EDF2
colorText:          #1F2937
colorTextSecondary: #667085
colorSuccess:       #3F7D5A
colorWarning:       #9A6B24
colorError:         #9B3A3A
borderRadius:       8
controlHeight:      34
fontSize:           14
```

颜色值可根据现有品牌规范微调，但必须维持低饱和、专业和安静的整体观感。正文和背景需满足可读性对比要求，不能只靠颜色表达状态。

### 3.3 字体与数字

- 使用系统无衬线中文字体栈，例如：`-apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei", "PingFang SC", sans-serif`。
- 页面标题建议 20-22px、600 字重，不使用超大标题。
- 分区标题建议 15-16px、600 字重。
- 正文和表格以 13-14px 为主。
- 辅助文字为 12px 灰色。
- KPI 数字使用 24-28px、500-600 字重，并启用等宽数字。
- 不使用负字间距，不根据视口宽度缩放字体。

## 四、全局布局

使用固定左侧导航栏和顶部标题栏。

### 4.1 左侧导航

- 展开宽度约 220-240px，折叠宽度使用 Ant Design 规范值。
- 支持折叠，折叠状态持久化。
- 顶部放置简洁的系统名称，不使用大幅品牌图。
- 导航结构：客户、样品、正式订单、供应商。
- 样品展开后包含：样品模板、样品订单、样品订单流程。
- 正式订单展开后包含：正式订单列表、正式订单流程。
- 选中项使用浅蓝背景、商务蓝文字和图标。
- 使用 `@ant-design/icons` 中语义明确的图标，不手绘 SVG。
- 折叠后图标提供 Tooltip。

### 4.2 顶部标题栏

- 高度控制在约 56-64px。
- 显示面包屑、当前模块、页面标题和必要的业务信息。
- 页面级主要操作可以放在标题栏右侧，例如“新增客户”“新建订单”。
- 不在顶部堆放无业务价值的装饰和冗余欢迎语。

### 4.3 内容区

- 使用约 20px 的页面内间距，窄屏按 12-16px 调整。
- 页面区域使用清晰的纵向节奏，常规区块间距 16-20px。
- 页面章节采用白底、1px 浅灰边框和 8px 圆角。
- 不要在卡片中继续嵌套卡片。表格、筛选条和分页尽量组成一个完整工作区。
- 只有独立指标、重复业务对象、弹窗和确实需要边界的工具区域才使用卡片。

## 五、页面标准结构

列表页面优先采用以下结构：

```text
页面标题区：标题、简短业务统计、主要操作
可选 KPI 区：仅展示真正有决策价值的 3-4 项指标
筛选工具条：常用条件、展开更多、查询、重置
数据工作区：表格或条状列表
分页区：总数、每页数量、页码
```

KPI 不要设计成大面积彩色卡片。使用一行紧凑的白色指标区，可以通过竖向分隔线分成多个指标单元。只有当指标能帮助运营判断工作量或异常时才展示。

图表只用于有实际含义的趋势或状态分布，例如不同订单阶段的数量分布；不要为了丰富页面而添加图表。流程页优先使用状态计数和列表，不使用占据大面积的装饰图表。

## 六、筛选与搜索

- 筛选区使用白底工具条，常用条件保持一行，窄屏允许换行。
- 主要输入框宽度稳定，不因内容或加载状态改变布局。
- 查询和重置按钮放在筛选条件末尾。
- 较少使用的条件放入“更多筛选”展开区或抽屉。
- 时间条件使用范围选择器。
- 客户、供应商等关联字段使用可搜索选择器，支持清空。
- 提交搜索时同步 URL 查询参数，使刷新、返回和分享链接能够保留筛选状态。
- 搜索请求做合理防抖，切换筛选或页面时处理并发请求，避免旧结果覆盖新结果。
- 所有列表默认每页 5 条，使用服务端分页。

## 七、数据展示

### 7.1 客户列表

客户必须采用条状展示，不改成营销式卡片网格。

每条客户记录应清晰展示：

- 客户名称和客户编号作为主识别信息。
- 客户分类、公司、联系人、联系电话、微信号。
- 客户状态和创建时间。
- 需求数量、样品订单数量、正式订单数量。
- 查看详情、修改、删除操作。

建议使用紧凑的横向信息布局或经过样式控制的 `Table`。主信息靠左，统计信息居中或靠右，操作固定在最右侧。操作按钮使用图标加文字或紧凑操作菜单，危险操作不得与普通操作视觉等价。

### 7.2 表格

- 使用 Ant Design `Table`，表头浅灰背景。
- 行高紧凑但保证点击区域，行悬停显示浅蓝灰底色。
- 文本列左对齐，数值和金额右对齐，状态居中或左对齐保持一致。
- 编号、金额、数量和日期宽度稳定。
- 长文本省略并提供 Tooltip；详情页显示完整内容。
- 操作列固定在右侧，避免横向滚动后丢失操作。
- 宽表格允许横向滚动，不强行压缩到无法阅读。
- 加载时使用表格骨架或标准 loading，不能让布局塌陷。
- 空数据使用简洁的 `Empty`，并在合适时提供创建入口。

### 7.3 状态标签

- 使用低饱和语义色的 `Tag`、Badge 色点或图标加文字。
- 草稿使用中性灰蓝；进行中使用商务蓝；完成使用克制绿色；中止/异常使用暗红；警告使用棕黄色。
- 状态必须同时显示文字，不能只用颜色。
- 同一状态在所有页面中使用一致颜色和文案。

### 7.4 操作按钮

- 页面主要操作每个页面最多突出一个 Primary Button。
- 查看、编辑等次要操作使用普通按钮、文本按钮或图标按钮。
- 删除、中止使用危险样式，并要求二次确认。
- 使用 Ant Design 图标；陌生图标必须提供 Tooltip 和无障碍名称。
- 不使用大量相同视觉权重的彩色按钮。

## 八、各业务页面设计

### 8.1 客户页面

- 标题区右侧提供“新增客户”。
- 筛选条件包括客户名称、客户编号、公司、联系人、联系电话和客户状态。
- 客户条目点击主信息或“查看详情”进入客户详情。
- 新增和编辑可使用独立页面或宽抽屉；字段较多时优先使用独立页面或宽抽屉，不使用狭窄小弹窗。

### 8.2 客户详情

- 顶部使用紧凑的信息摘要区，不设计成大面积人物档案卡。
- 展示客户名称、编号、公司、分类、联系人、联系方式、状态和备注。
- 右侧提供编辑客户操作。
- 下方使用 Ant Design `Tabs` 或嵌套路由展示：客户需求、样品模板、样品订单、正式订单。
- 标签上可显示相应数量。
- 每个标签内只展示当前客户数据，并保留搜索、分页和新增操作。
- 刷新后保持当前标签，浏览器返回操作符合预期。

### 8.3 样品模板

- 列表突出模板名称、编号、所属客户、产品名、规格摘要、供价、状态和创建时间。
- 操作包含：复制为新模板、加入样品订单、加入正式订单、查看、修改、删除。
- “复制”使用 Dropdown/Menu 选择目标，不使用三个并列的复制按钮。
- 模板详情按产品基础信息、规格、单份供价分区展示。
- 新建模板状态默认显示“草稿”。
- 产品品类、肉类等级、货品状态使用普通文本输入框。

### 8.4 样品订单和正式订单列表

- 展示订单名称、编号、客户、产品明细数量、产品摘要、创建时间、交付时间、流程状态和中止状态。
- 使用者可以快速进入详情、修改或删除。
- 中止订单在列表中有明确但克制的异常标识。
- 产品较多时展示前 1-2 个产品名和“另有 N 项”，不要把全部产品塞入列表行。

### 8.5 订单编辑器

订单包含多个产品，表单必须分为：

1. 订单基本信息。
2. 产品明细。
3. 整单交付信息。
4. 整单结账信息。
5. 备注和操作区。

产品明细使用可展开列表、分区编辑器或稳定的明细表格。每条产品包括产品基础信息、规格、供价、数量和可选供应商。

- 从模板加入后，清楚标记来源模板。
- 支持继续加入其他模板。
- 支持调整数量、选择供应商和删除明细。
- 供应商为空时显示“本公司供应”或“无外部供应商”，数据库仍保存空值。
- 页面底部提供固定或易于找到的“保存草稿”和“提交订单”。
- 提交时定位首个错误字段，并保留所有已填写内容。

### 8.6 订单详情

- 顶部展示订单名称、编号、客户、流程状态、中止状态、创建时间和交付时间。
- 使用简洁的 Steps 或状态轨迹表现流程，不做大型彩色流程图。
- 产品明细采用可扫描表格，点击或展开查看完整产品属性和规格。
- 交付、结账、备注和流程记录分区展示。
- 关键操作放在右上方或底部稳定操作区。

### 8.7 样品订单流程

使用状态分段导航、Tabs 或紧凑统计条展示：

```text
全部
样品沟通
工厂沟通
样品制作中
样品制作完成
顾客送样
成品确定
已中止
```

- 每个状态显示订单数量。
- 切换状态时更新 URL 和服务端查询条件。
- 支持按客户、订单、产品、创建时间和交付时间筛选。
- 每条订单右侧提供查看详情、进入下一流程和中止；已中止时显示取消中止。
- 最终状态不显示“进入下一流程”。
- 中止弹窗必须填写原因，取消中止需要确认。
- 状态推进成功后就地刷新当前列表和各状态数量，避免整页跳转。

### 8.8 正式订单流程

复用样品订单流程页面的结构和组件，但状态替换为：

```text
全部
订单沟通
工厂沟通
订单制作中
订单制作完成
送达顾客
已中止
```

不得复制一套难以维护的页面代码，应通过流程配置、类型和公共组件实现差异。

### 8.9 供应商

- 采用与客户列表一致的条状企业档案风格。
- 展示供应商名称、编号、联系人、联系电话、地址、状态和创建时间。
- 提供新增、查看、修改和删除。
- 当前阶段不增加无需求依据的供应商分析大屏。

## 九、Ant Design 5 实施要求

- 使用 `ConfigProvider` 集中配置主题令牌、中文语言环境和组件尺寸。
- 优先使用 Ant Design 标准组件：Layout、Menu、Breadcrumb、Table、Form、Input、Select、DatePicker、InputNumber、Tabs、Tag、Badge、Drawer、Modal、Dropdown、Tooltip、Descriptions、Steps、Pagination、Empty、Skeleton 和 Result。
- 不重复造基础控件，也不通过大量 CSS 强行覆盖组件内部结构。
- 对确需调整的样式使用稳定的项目级类名或 CSS Module，不依赖脆弱的深层 DOM 选择器。
- 表单标签、校验信息和帮助文字保持对齐。
- 日期、金额、数量和空值展示通过统一格式化函数处理。
- 状态颜色、状态文案和流程顺序通过统一配置管理。

## 十、FastAPI 对接方式

- 依据 FastAPI 的 OpenAPI Schema 生成或维护 TypeScript 类型，避免前后端字段漂移。
- 建立统一 API Client，集中处理 base URL、认证、错误转换、取消请求和超时。
- 服务端分页接口统一接收 `page`、`pageSize` 和筛选参数，返回 `items`、`page`、`pageSize`、`total`。
- FastAPI 校验错误应转换成用户可理解的表单或消息提示，不直接把原始错误对象显示给用户。
- 流程推进、中止和恢复调用专用动作接口，不通过普通订单编辑接口直接修改状态。
- 写操作成功后精确刷新相关订单、列表和状态计数，避免无差别刷新整个应用。

## 十一、响应式设计

- 桌面端以高效表格和固定导航为主。
- 中等宽度下允许筛选项换行，保持按钮和输入框完整。
- 移动端导航改为抽屉或折叠模式，内容区改用 12-16px 间距。
- KPI 指标改为单列或两列。
- 宽表格使用横向滚动；不要用极小字体硬塞。
- 客户条目可在移动端变为单列信息块，但不能丢失关键状态和主要操作。
- 移动端操作可以收纳到 More 菜单，危险操作仍需确认。
- 任何视口下文字、按钮、状态标签和分页控件都不得重叠或溢出。

## 十二、可用性与无障碍

- 所有输入有可见标签，不能只依赖 placeholder。
- 图标按钮有 Tooltip 和 `aria-label`。
- 键盘可以完成筛选、表单编辑、弹窗确认和主要列表操作。
- 焦点状态清晰，弹窗关闭后焦点回到触发元素。
- 状态和错误不能只靠颜色表达。
- 删除、中止、流程推进等操作在执行期间禁用重复点击。
- 保存成功、失败和校验错误均提供明确反馈。

## 十三、交付与验证要求

先给出简洁的页面结构、组件划分和设计令牌方案，然后直接实施，不停留在静态描述。完成后必须：

1. 运行项目已有的格式化、Lint、类型检查、测试和构建命令。
2. 使用真实浏览器检查主要页面，而不是只判断代码能够编译。
3. 至少检查常用桌面、窄桌面和移动端三个视口。
4. 检查筛选换行、宽表格滚动、固定操作列、抽屉/弹窗、长文本、空数据和加载状态。
5. 检查页面是否出现文字重叠、按钮溢出、布局跳动或无法操作的控件。
6. 确认没有渐变、玻璃效果、夸张阴影、装饰性插画、营销式大标题和无意义图表。
7. 最终汇报已完成页面、公共组件、设计令牌、FastAPI 接口对接情况、验证结果以及尚未实现或仍待确认的事项。

不要只生成一张静态首页。第一屏必须是可使用的业务工作台，并且客户、模板、订单和流程页面采用一致、可复用、可维护的企业级设计体系。
